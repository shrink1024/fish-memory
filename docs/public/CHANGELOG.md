# 版本说明

## 0.4.1（2026-10-29）

- 单独辅助接口的连接顺序改为：填地址和密钥 → 连接并获取模型 → 下拉选择模型 → 保存并使用。模型下拉框始终可见，获取列表后可选，不需要先知道模型名称。
- 保留手动填写模型 ID；获取列表只读取接口模型目录，不调用模型生成，也不代表所选模型已通过生成测试。

## 0.4.0（2026-10-29）

**界面改版**

- 管理窗口只剩一条标题栏，状态和“现在整理”也在上面。窗口可以拖动、拖边角调大小、最大化，大小和位置会记住；手机上自动全屏。
- 页签从六个并成四个：资料、本轮、记录、设置。预设应用移到设置里，收发移到记录里。
- 资料列表每条前面有灯：蓝灯常驻、绿灯按需、空心灯关闭，点灯就能换档位。条目旁边标出“改”（和原书不同）、“新”（鱼忆新建）、锁（受保护）、“待核对”。可以按档位筛选，也可以只看有改动的条目。列表和详情之间的分隔线可以拖。
- 条目详情顶部是“常驻 / 按需 / 关闭”三个按钮和“保护正文”开关。
- 多选改为直接在列表里勾选，按住 Shift 可以连选，底部一条操作栏改档位。
- 导出和导入收进资料页右上角的“⋯”，各是一个简短的对话框。
- 设置分成常用、辅助模型、预设应用、高级四组，说明文字收进 ⓘ。单独接口的多套配置合并进“使用的连接”下拉框。保留轮数改完就生效，不用再点保存。
- “本轮”按常驻、关键词触发、这一轮选入分组列出发送的资料。
- 后台刷新时，各页面保持原来的滚动位置。

**修复**

- 辅助模型的服务方用内容审核拦下某一批世界书扫描时，整个初始化会失败，重试也会把同一批原样再发一次，换模型之前一直卡住。现在被拦的一批会拆开重发，拆到单条仍被拦的条目先不扫描，按原世界书的设置发送，并在资料里标“未扫描”；初始化照常完成，并提示有几条被拒收。换用审核较宽松的辅助接口后，把这些条目设为常驻或按需就会重新扫描。同步原书更新时，已有条目的新版被拦，这条保留原来的资料和剧情改动，不算同步完成，“原书有变化”的提示也会留着。一次扫描最多拆分 16 次，最多多发 32 个子请求（原本的各批另计），接口全部拒收时不会无限重发。
- 被内容审核拦下时，报错直接说明这是模型服务方的审核，附上拒收原因代码（例如 `PROHIBITED_CONTENT`），并建议在“设置 → 辅助模型”换接口，不再笼统地写“检查接口返回与模型设置”。
- 出错时，错误框里直接有“导出本次问题”。

**新增**

- 作者规则新增 `gate`，和 `trigger` 配对：`trigger` 管“关键词出现了必发”，`gate` 管“关键词没出现不能选”。条目的原书关键词没有出现在玩家本轮输入或最近 4 楼正文里时，不进这一轮的选材目录，不占选材名额；作者规则的 `always` 也不会越过它。原书蓝灯和玩家设为常驻的条目不受影响；扫描时被判为重要的条目不会因此绕过 `gate`，资料页按按需显示。“本轮”页会列出这一轮因此没进目录的条目。用了 `gate` 的卡需要这一版鱼忆，旧版会提示规则里有未知操作。

本地 644 项程序测试及 53 文件安装构建通过。新窗口只在演示页和合成测试里验证过，未在真实酒馆、TT、Luker 或真实模型上验证。

## 0.3.3（2026-10-27）

**修复**

- TauriTavern 2.4.0 提示“当前 TT 缺少鱼忆所需的保存队列接口”、无法保存。鱼忆现在接受 TT 2.4 的新接口版本，保存方式不变；未知版本仍会拒绝。尚未在 TT 2.4 实机上验证。
- 顶栏的鱼形按钮不再冒充酒馆抽屉，避免在 TT 现代界面里把一整排顶栏按钮点死。
- 部分广告拦截插件会拦下鱼忆的一个文件，导致整个插件加载失败、只显示 `[object Event]`。该文件已改名。今后再有文件被拦截、缺失或浏览器不支持，鱼忆会弹出提示，写明是哪个文件、该怎么处理。
- 手机上从条目详情返回列表时，不再跳回列表顶部。
- 手动改的档位（单条或批量）在重 roll 那条回复后会丢失，变回扫描时的档位。现在会保留。

**新增**

- 资料页可按档位筛选，并多选或选中全部筛选结果，一次批量改档位，一次最多 1000 条。列表显示“正文已保护”“部分保护”。
- 记忆迁移：可以把动态世界书、故事脉络和物品导出成一本酒馆世界书，给新聊天使用；也可以把以前写的总结（世界书 JSON、TXT 或当前附加世界书）导入为补充记忆，不换主书，不调用模型。
- 单独辅助接口可以保存多套命名配置，一键切换，最多 20 套，密钥只保存在当前浏览器。

导入的补充记忆不随重 roll 或删楼消失。本地 622 项程序测试及 53 文件安装构建通过。未在真实酒馆、TT 2.4 或真实模型上验证。

## 0.3.2（2026-10-21）

**主世界书由鱼忆决定发送**：

- 每轮只发送鱼忆选定的主世界书条目。没选中的条目这一轮不会被关键词、递归或其他脚本点亮；选中的不再被原生预算、概率、分组丢掉。插入位置、深度和顺序仍按原书。蓝灯默认仍每轮发送。
- 原书条目的粘性、冷却、延迟不再按楼层计时。初始化时这些数值作为提示交给扫描，写进条目的“何时提取”；发送前选材会看到当前楼层数。历史窗口不再因鱼忆接管的条目带计时而停止省略。
- 卡里的脚本在原书里开关条目时，不再提示“原书已变化”，鱼忆按当前开关处理。扫描时关闭、后来被打开的条目先按原书方式发送，可点“只同步变化的条目”扫描。
- 含提示词模板激活条件（`@@if` 等）的条目、扫描后新加的条目，仍按原书方式发送。
- 作者规则新增 `trigger`：条目的原书关键词出现在玩家本轮输入或最近 4 楼正文里，就直接选入，不经过模型判断。作者规则的自然语言要求也会交给选材参考。规则写法见 `src/rules/README.md`。

**新增**

- 每条资料可在“资料”页调档位：常驻（每轮发送）、按需（由选材决定）、关闭（不发送、不维护），并可“恢复扫描时的档位”。只改存档里的动态副本，不改原书。
- 收发记录按请求类型标注：酒馆正文生成、后台请求（其他扩展或角色卡）、酒馆代写。

**修复**

- 长存档逐条删楼时，每删一楼都会取消并重发同一批后台整理。删楼或改选落在正在整理的那一批之后时，不再取消，整理完从当前剧情接着补记一次；仍遵守玩家暂停。
- 待补记的楼层很多时，发送前选材会带上全部待补记正文，导致请求过大、网关超时。现在近期轮次完整保留，更早的待补记正文只带最新约 4 万字。
- 初始化途中刷新，可能整本世界书重扫。断点现在只比对真正进入请求的预设条目与偏好；改动没勾选的预设条目不再作废进度。旧版本保存的断点升级后会重扫一次。

本地 598 项程序测试、123 文件检查及 50 文件安装构建通过。未在真实酒馆、真实模型上验证。

## 0.3.0（2026-10-16）

建立记忆提速（FM-014/016/018），以及预设应用的头尾包裹：

- 辅助任务默认低思考强度。扫描、选材和整理不再照搬正文预设的思考强度；设置 → 扫描速度 → “辅助任务思考强度”可改为中、高、交给模型或沿用酒馆预设。单独接口不接受该参数时自动去掉重发一次，之后不再发送。
- 原书里关闭的条目先不扫描，原书启用后点“只同步变化的条目”再扫描；纯脚本条目（只有 EJS 代码与 @@ 指令）由程序直接锁定为规则，不调用模型。
- 历史剧情扫描与后台维护：动态资料较多时，每批只附上与本批剧情相关的条目全文（标题、原书关键词命中，常驻条目，最近维护过的条目），其余只列目录；模型需要改目录里的条目时，程序补发这些条目单独更新一次。资料不多时照旧整份附上。
- 常驻脉络改为追加：每批只写新增的一段，不再整段重写；超过 8000 字时自动整理压缩。
- 初始化扫描历史时每批最多 4 万字（平时维护仍按原设置），批数更少。
- 预设应用改为头尾包裹：选中的条目按原文和原角色放在鱼忆任务之前（头部）或任务输入之后、请求最后（尾部），不再作为引用资料塞进系统提示词。默认沿用预设本身的位置（排在聊天记录之后或按深度插入的算尾部），可逐条改。已保存的选择继续有效。
- 提升提示词质量，减少报错与中断情况：重写辅助任务的说明与完成核对，明确输入资料的处理边界，补充长文本与复杂剧情的处理说明；辅助任务的输入字段规范化，剧情正文按存档资料标注来源；异常返回按类型区分处理，减少失败重试。
- 预设条目推荐规则调整：语言、术语、表达风格、题材宽容度与内容处理说明等条目可被推荐，仍排除会破坏任务输出格式的条目。

- “导出本次问题”里的鱼忆版本号自 alpha.5 起一直写死为 0.1.0-alpha.5，现在按实际版本填写。
- 拒答后的重试在单独接口上也会把重述放在资料之后；维护提示词里的物品清单归属改为“玩家角色”，与剧情消息的新标注一致。

本地 572 项程序测试、117 文件检查及 50 文件安装构建通过；隔离演示验证预设头尾选择与发送前预览。未调用真实模型，提速幅度待真实接口复测。

## 0.1.0-alpha.7（2026-10-14）

依据类脑帖反馈：

- 原书更新后可“只同步变化的条目”：新增条目单独扫描、删除条目移除、只改元数据的条目直接更新；剧情没改过的条目换成新版，剧情改过的条目把旧原书、新原书与当前版本一起交给模型合并。受保护片段不进入合并请求。同步作为一次提交保存，回滚到同步前会重新提示同步。（FM-002）
- 新增“记忆范围 → 仅动态世界书”：只更新已有世界书条目并按需选材，不新增条目或晋升人物，不维护、不发送故事脉络、事件和物品，历史窗口不省略原文；已有资料保留，可随时切回。（FM-004）
- 单独辅助接口的地址、模型与密钥保存在本浏览器，刷新后继续使用；改回沿用酒馆连接会清除。（FM-001）
- 悬浮气泡默认改为小图标，任务进行中或需要处理时显示小圆点；可在管理窗口顶部切换为带文字。（FM-003）
- 维护与整理的输出上限按当前脉络和最长片段估算（最多 32768，仍受模型明确上限约束），避免长档每次维护被截断；脉络超过 8000 字时自动整理压缩。（FM-016）
- 世界书分类可同时发出多批（设置 → 扫描速度，默认 3 批，可调回 1），断点仍按顺序保存。（FM-018）
- 提示词模板检测不再依赖扩展文件夹名，并区分“未安装”“被停用”“未加载”和“模板内部开关关闭”四种原因。（FM-019）
- 回滚后立即重新核对原书变化，面板与历史窗口不再沿用回滚前的判断。

本地 539 项程序测试、109 文件语法与入口检查、47 文件安装构建通过；隔离演示页核对了气泡、记忆范围与扫描速度设置。本轮未调用真实模型，未重新进行 ST、TT、Luker 真实宿主验收。

## 0.1.0-alpha.5（2026-10-09）

- 自动维护频率增加“自定义”入口：可选每 1、3、5 次 AI 回复，或填写 1–1000 的整数，默认仍为 3 次。按 AI 回复楼计数，玩家发言不计入；保留已有设置、长文本提前分批补记及手动补记，界面同时显示当前生效间隔。
- 修复前置等待期间重复发送、切换聊天和输入变化后旧生成仍继续的问题；候选切换不会等待后台模型结束才完成界面操作。补齐酒馆助手静默生成与无关结束事件的隔离，防止误锁发送、丢弃玩家本轮选材或过早清空正文资料。重生成、切候选和续写进入正文阶段后恢复输入。
- 辅助请求沿用酒馆连接参数，通过独立传输发送，避免触发正文模板事件、执行资料中的宏或套用正文输出清理。聊天补全与 textgenerationwebui 有程序覆盖，其他后端需单独兼容接口。
- 模型返回的单个完整 JSON 可以带解释、围栏或思考包装，支持模板预填思考开头、仅返回闭合标记的格式。解释中的普通括号不再被误判为第二份 JSON；多个有效结果仍拒绝猜选。格式或任务校验失败最多纠正一次，纠正要求放在系统说明中，共用原请求时限；网络错误、截断、空正文、不完整 JSON 和取消不重复调用。仍然无效则整批不保存，保留待补记原文。
- 辅助输出按任务估算，保留酒馆配置的更高预算；有明确模型输出上限时按上限约束。初始化除字数限制外，每批最多 24 条；选材预算随名额与 ID 长度调整，常驻条目不占按需名额。只有明确结束标记才报告截断，宿主丢失原因时提示原因不确定。单独接口适配 GPT-5／o1／o3／o4 的输出长度参数；文本补全保留 instruct 模板终止串。
- 正常发送和停止本轮发送均保留已发出的后台维护，结果等待选材结束再校验保存，减少反复丢弃。停止本轮及时释放过期选材的等待，同时暂停后续自动维护，新的助手回复再恢复；显式停止维护仍取消对应任务。两种连接都将取消信号传入网络请求，但不能保证供应商同步停止计费。
- 修复初始化取消后仍显示运行、世界书改绑后无重扫入口、物品开关随分支回退，以及单条重置丢失原简介的问题。候选回退尽量保留玩家对现存条目的手改；重叠冲突标待核对，废弃剧情不随手改带回。
- 无可用摘要时保留历史原文；世界书含粘性、冷却、延迟条件或无法读取确认时，暂停本轮窗口裁剪。另记录实际交给维护模型并成功保存的楼层，被跳过的隐藏消息取消隐藏后仍保留原文。alpha.4 及更早版本的旧档，已处理的历史视为已读，升级后照常省略；仅缺少记录的未发布候选存档保留无法确认的原文。时间条件条目保留原生记录；面板显示实际省略楼数和兼容提示。
- 维护输入移除历史来源数组，保留完整可写正文。合成样例请求字符数减少约 6%–58%；大世界书仍可能有较高输入成本，此数字不是 token 或账单节省比例。
- 存档以无损去重的 schema 3 保存，自动读取旧 schema 2；不删回滚历史。不同正文的 200 轮样例从约 14.4 MB 降至 4.4 MB。历史仍增长，仍需完整聊天保存与回读；多个客户端同时写同档不提供原子协调。**alpha.4 及更早版不能读取新格式；降级必须恢复升级前的插件和完整聊天备份。**
- 受保护词使用本次请求独有的引用，返回后在原字段权限内还原，避免摘要提到受保护地名就无法维护。拒绝跨字段、旧请求或未知引用；早期已被写坏的通用占位符需要手动修正，无法猜回原词。过滤外部隐藏原文，修正 MVU 所选候选身份，补齐日志凭据过滤；同地址只改辅助模型可沿用本页密钥，更换地址不会带走旧密钥。
- 损坏或不受支持的存档显示载入失败和原因。改绑世界书后就绪事件不再反复取消重扫，重扫成功前卡侧读取拒绝旧书资料。仅范围上下文改变时，保留分类输入未变的扫描批次，历史草稿仍按新范围重做。
- 旧版写进记忆的“[受保护资料]”占位符可以在原字段保留或删除，不再让维护反复失败、重复计费；复制、挪到其他字段或增多仍被拒绝。酒馆助手按生成 ID 停止自身请求时，不再取消玩家本轮发送。单独接口遇到推理模型时不再限制输出长度，玩家填写上限时照常发送。
- 世界书检查区分无主绑定、角色未就绪、文件缺失、读取失败与合法空书；“重新检查世界书”可刷新当前主书的占位空缓存，不改原书、不调用模型。

本轮最终发布检查通过 498 项程序测试。此前真实浏览器验收覆盖适配器的发送、切档、候选和模板边界，完整控制器另通过 ST 原生聊天 HTTP 存储验证扫描、取消重试、后台并发、候选手改、窗口和重载；本轮新增证据为本地事件回放、协议和存档测试，不能把此前浏览器结果当作本轮整插件复验。新版整插件 UI 与 Gemini／DeepSeek／Claude／GPT-5 的真实模型调用尚未补验。本次作为实验性公测更新发布；未调用真实模型或修改玩家存档。原生 Kobold／Novel／Horde 辅助路径尚未恢复，需单独兼容接口。
