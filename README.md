# 鱼忆｜动态世界书与记忆

鱼忆是一个面向 SillyTavern 单角色聊天的独立扩展。它为角色卡的**主绑定世界书**建立随存档更新的动态副本，并根据当前对话选择资料、整理故事脉络、人物、事件和玩家物品。原世界书不被改写；其他世界书、卡作者的变量、任务和玩法仍由原来的工具管理。

当前候选：**0.1.0-alpha.1，实验性公测**。本轮已完成隔离酒馆的扫描、生成、保存、刷新、候选删除、失败回退、旧档恢复、停用／卸载，以及本地Git安装／更新和成对备份回退验证。宿主验证均使用本地合成响应，未调用真实模型。具体范围以 [兼容说明](COMPATIBILITY.md) 和 [变更说明](docs/public/CHANGELOG.md) 为准。模型可能错记、漏记或选错资料；本版本不承诺普遍改善叙事质量，也不承诺节省调用费用。

## 安装前

- 使用带有主绑定世界书的单角色卡，并先备份要测试的聊天、角色和世界书。建议从聊天副本开始。
- 安装并启用 [ST-Prompt-Template／提示词模板](https://github.com/zonde306/ST-Prompt-Template)，作者为 zonde306。本轮隔离验证组合为 **SillyTavern 1.19.0 + ST-Prompt-Template 1.17.9**，不代表其他版本已经验收。
- 普通卡无需适配，无需安装酒馆助手、MVU或任何特定角色卡。MVU只读协作是可选项。
- **总开关和新存档默认启用。** 辅助模型、主世界书和模板就绪时，新开场档会自动建档，产生额外模型调用；请先确认使用的连接与费用。

安装方式、更新和退出步骤见 [INSTALL.md](INSTALL.md)。安装包解压后的 `st-dynamic-world-memory` 目录应直接包含 `manifest.json` 与 `index.js`，将它放入酒馆的 `public/scripts/extensions/third-party/`。只安装一份鱼忆，再刷新页面。玩家安装不需要另行配置 Node.js。

发行仓库：[shrink1024/fish-memory](https://github.com/shrink1024/fish-memory)。在酒馆扩展管理器中选择“安装扩展”，填入 `https://github.com/shrink1024/fish-memory`；不要同时保留另一份离线安装。勿将开发工作区整库作为安装内容。

## 第一次使用

1. 点击酒馆顶部世界书按钮旁的鱼形按钮。也可从扩展设置中的“鱼忆｜动态世界书与记忆”打开管理窗口。
2. 在“设置 → 辅助模型连接”确认连接。默认沿用酒馆当前连接；也可以临时使用单独的兼容接口。
3. 新档只有开场、尚无玩家正式消息时，会在条件齐备后自动建立记忆。**已有剧情且尚未建立鱼忆记忆的旧档，需在“资料”点击“手动扫描 / 重试初始化”（部分状态显示“建立此存档记忆”）**，分批扫描当前保留的剧情。已初始化档及继承分支不会自动重扫。
4. 扫描完成后正常聊天。发送前会选择资料，回复后会维护记忆；输入区和管理窗口可查看阶段、耗时、停止及重试入口。

扫描中继续发送会走酒馆原生流程，不使用半份动态资料；新剧情随后补记。自动初始化失败或被停止后不会因刷新不停重试，可以手动重试。关闭“启用此存档的记忆”只暂停当前档；“插件总开关”影响所有档，已有动态资料保留。

**单独的兼容接口只在当前页面有效。** 刷新后恢复沿用酒馆连接；接口密钥不写入存档。切换连接前等待任务结束或先停止。沿用酒馆接口时，“停止”通常只取消鱼忆等待和采用结果，不能保证供应商立即停止运行或计费。

## 调用、资料与效果检查

初始化、分批扫描、每轮前置选材、回复后维护和事件整理都会调用辅助模型；长档与大世界书可能需要多次调用。“扫描当前预设”和“试选一次”也会调用模型。发送前只读预览不调用模型。调用量和费用取决于资料量、设置、模型与失败重试，不能当作固定每轮一次。

在“资料”查看动态条目、原书差异与修改依据；“本轮”查看实际选材；“维护与记录”查看进度与失败。可以手动修改资料，或只重置某一条。单条重置使用本档建立时保存的基准，不等于同步作者后来更新的同名世界书。检测到原书新增、修改或删除时，鱼忆会提示并暂停自动维护和旧基准重置；发送前可明确选择原书发送或取消。更换卡或世界书前请按 [更新与重建说明](INSTALL.md#卡或世界书更新) 备份并检查。

建议用一项明确变化来试，例如“钥匙交给甲，随后甲把钥匙归还玩家”：核对下一轮的记忆、选材和最终回复是否一致。单纯看到“已完成”只能证明流程完成，不能证明事实判断正确。

每个分支独立保存，当前选中候选决定剧情。普通旧楼文本的事后编辑不主动触发记忆重算；仍在发送范围内的原文会使用当前文本。dev.11中已经错记、且旧候选身份已丢失的档无法自动推断修正；请先备份，再按当前有效剧情重新扫描。确需按编辑后的完整剧情重建时，先备份，再在“设置 → 重新扫描此存档”执行；成功后会替换动态资料，包括手动改动。

玩家物品清单可以关闭：停止维护和注入，保留数据，重新开启后追平停用期间的剧情。卡已有自己的物品机制时可关闭。鱼忆不读取或改写卡的整套变量；可选MVU协作只参考玩家指定的少量字段。

## 历史窗口、暂停与退出

历史窗口默认关闭。开启后，鱼忆仅让**已有有效记忆覆盖、且超出近期范围**的原文退出当次模型发送；原聊天正文保留。与其他自动隐藏工具同时使用的组合未获完整支持。

本候选采用当次请求过滤，不再通过持久隐藏原楼管理窗口。已在隔离酒馆验证实际发送省略旧原文、保留摘要，且聊天文件没有新增持久隐藏；总开关关闭时载入dev.11旧档及分支的恢复也已验证。扩展管理器停用／卸载后的完整原文发送也已验证。曾使用 dev.11 历史窗口的旧档仍可能带有旧隐藏标记：保留备份，在新版中逐档打开并确认恢复保存，或使用随包 [离线恢复工具](recovery.html) 处理导出的 JSONL 副本。直接卸载不能执行尚未打开旧档的恢复代码；详情见 [安全退出与旧档恢复](INSTALL.md#安全退出与-dev11-旧档恢复)。

## 失败时如何继续

- 前置选材失败：可重试、明确选择本轮用原书发送，或取消。原书发送不采用失败的选材结果。
- 后台维护失败：已有记忆保留，待补记的原文继续保留，可继续聊天或点“补记新剧情”。不要把旧记忆当作已跟上最新剧情。
- 停止扫描／维护：保留已提交的资料，迟到结果不再提交。保存提交阶段不能撤回；停止后查看状态再操作。
- 发送前置阶段停止：不继续生成新的助手正文，但酒馆可能已经保留一条本轮用户消息。重发前先检查聊天，避免重复发送。
- 设置保存未确认：鱼忆保存后会回读核对；失败或酒馆只排队未写入时，本页恢复修改前的设置。磁盘可能已经写入，不保证随本页回滚；等辅助生成结束或连接恢复后重试并核对。
- 初始化依赖未就绪：查看面板列出的主世界书、单角色聊天、模板和模型条件，不必反复重新安装。

## 问题反馈与隐私

遇到问题时，刷新前进入 **收发 → 实际记录 → 导出本次问题**，优先导出当前档的问题包。按 [反馈模板](docs/public/FEEDBACK.md) 补充预期与实际行为、发生步骤、版本和启用的其他工具，检查隐私内容后提交到 [仓库 Issues](https://github.com/shrink1024/fish-memory/issues)。

日志只保留在当前页面内存，有数量与体积上限，刷新即清空，不进入鱼忆模型上下文。“导出本次问题”面向当前存档；**“导出全部”包含本页仍保留的其他聊天记录**，两者不同。问题包和日志可能含私人剧情、预设、角色信息及提示词；凭据过滤不等于匿名或完全脱敏。请先检查，自行删去不愿提供的内容，也可以只提供最小复现文字。

收发查看器记录的是当前页面能够观察到的请求边界；经酒馆代理时看到的是浏览器发给酒馆的内容，不保证就是供应商最终收包，也不保证捕获所有插件或传输方式。

## 公测边界

当前面向单角色聊天；群聊、多个客户端同时写同一档、复杂EJS主动读取、全部模型后端和第三方扩展组合未获完整支持。真实MVU组合、长期记忆质量、大存档成本仍需有限实测与公测。存档格式为 schema 2，其他旧开发格式不自动迁移；插件升级、换卡换书、重装与重新扫描是不同操作。详见 [兼容说明](COMPATIBILITY.md)。

鱼忆的灵感来自我的好朋友冷鱼交给我的项目。为了纪念她，我把这个插件取名为“鱼忆”。代码独立实现，维护者为 [shrink1024](https://github.com/shrink1024)。许可证尚未确定，当前没有授予开源许可证。
